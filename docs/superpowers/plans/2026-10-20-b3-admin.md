# B3 In-Game Administration (Block 15) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show B3's players, admins, penalties and commands per instance and offer four actions on B3's own database: lift ban, add ban, set group, lift warning.

**Architecture:**
- Pure catalog, status, masking and parsing live in `lib/b3-admin.mjs`.
- Named, parameter-bound queries live only in the Python helper (`op: 'query'`).
- `InstanceB3DatabaseService.query()` reuses the Block 14 password binding and short vault scope.
- `lib/instance-b3-admin-service.mjs` adds readiness checks, masking, the guard and audit.
- API routes and a React panel sit on top.

**Tech Stack:** Node ≥ 18 ESM with `node:test`, Express 5, React 19 (esbuild render tests), Python 2.7 + PyMySQL (eBc-B3 9096624).

**Spec:** `docs/superpowers/specs/2026-10-20-b3-admin-design.md`

## Global Constraints

- **Version and branch:** 4.18.13 on `control-4.18.13`. Code, comments, commits and repo docs are in English.
- **No SQL text from Node.** Every query is a name from the Python `QUERIES` table, executed with `cur.execute(sql, params)` (bound, `%s` paramstyle).
- **Paging:** `limit` 1–100, default 50. `offset` 0–1,000,000. `search` ≤ 32 chars. `reason` 1–255 printable chars. TempBan duration 1–525600 minutes.
- **Penalty filters:** `type` ∈ {Ban, TempBan, Permanent, Kick, Warning, any}, where Permanent means `type = 'Ban'`. `status` ∈ {active, expired, lifted, any}.
- **Masking without `config.manage`:**
  - An IPv4 address `a.b.c.d` becomes `a.b.c.x`; anything else becomes `x`.
  - A GUID becomes `…` plus its last 4 characters; a GUID of 4 characters or fewer becomes `…`.
- **Permissions:** reads need `diagnostics.read`. `ban`, `unban`, `group` and `lift` need `server.manage`.
- **Writes:**
  - Every write runs under the database service's per-instance lock.
  - `setGroup` also refuses with `B3_RUNNING` while B3 runs.
  - `addBan` writes `admin_id = 0` and `keyword = 'control'`.
  - A Ban gets `duration = 0` and `time_expire = -1`. A TempBan gets `duration = minutes` and `time_expire = now + minutes*60`.
- **Audit events** never contain IP, GUID, name or reason.
- **Tests:** every new test file is registered in `scripts/preflight-4.18.13.mjs`.

## Review Focus

1. Search text with `%`, `_`, `'` or backslash must be treated literally (escaped LIKE pattern, bound) and must never break the query. Tested in Task 2 (Python fake connection checks params) and natively in Task 7.
2. A viewer must never receive a full IP or GUID, including in the player detail (aliases, IP history) and in penalties joined with client GUIDs. Task 4 scans every read result.
3. Adding a ban to a client that does not exist, or a stale `clientId`, must fail with `B3_ADMIN_CLIENT_NOT_FOUND` and write nothing. Task 2 and native Task 7.
4. Lifting a penalty id that is a Ban (not a Warning) through the warning route must be refused with `B3_ADMIN_PENALTY_NOT_FOUND`. Tasks 2 and 7.
5. A TempBan whose `time_expire` equals now must be `expired`, matching B3's `time_expire > now`. Task 1.

### Task 4: Admin service

**Files:** create `lib/instance-b3-admin-service.mjs`; test `test/instance-b3-admin-service.test.mjs`.

**Produces:** `class InstanceB3AdminService({ store, database, environment, b3IsRunning, onEvent, now })`.
- Reads:
  - `players(id, { search, offset }, { full })`
  - `player(id, clientId, { full })`
  - `admins(id, { full })`
  - `penalties(id, { type, status, offset }, { full })`
  - `groups(id)`
  - `commands(id)`
- Actions:
  - `addBan(id, clientId, { kind, durationMinutes, reason }, actor)`
  - `unban(id, clientId, actor)`
  - `setGroup(id, clientId, groupId, actor)`

- Reads return objects with masking applied unless `full`. Penalties include `status` and `group` names.
- `setGroup` runs inside `database.withStartGuard` and checks `b3IsRunning` inside it.
- `commands` reads `plugin_admin.ini` (regular file, no symlink, ≤ 64 KiB) via `environment.read().b3Path`, otherwise `B3_ADMIN_COMMANDS_UNAVAILABLE`.

  - A ban duration out of range gives B3_ADMIN_INPUT_INVALID.
  - Audit events carry no IP, GUID, name or reason.
  - A missing commands file gives B3_ADMIN_COMMANDS_UNAVAILABLE.
