# Live Kick (Block 15b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Kick a connected player immediately by slot, verified before and after. The kick is offered from an online list, from online B3 player rows and as "ban and kick".

**Architecture:** A pure status parser and a separate kick packet builder; the console allowlist stays unchanged. `InstanceRconService.kick` verifies the target with `status`, kicks, then confirms. The B3 admin service marks online players and offers kick and ban-and-kick. API and UI sit on top.

**Tech Stack:** Node ≥ 18 ESM with `node:test`, Express 5, React 19, and the real CoD4x 21.2 Linux core in WSL for native tests.

**Spec:** `docs/superpowers/specs/2026-10-20-live-kick-design.md`

## Global Constraints

- **Version and language:** 4.18.14 on `control-4.18.14`. All repo text is English.
- **Slot:** an integer from 0 to 63, sent as 1–2 decimal digits. Never a name, never `all`.
- **Reason:** `^[\x20-\x7e]{0,126}$` without `"` `;` `%` `/` `\`. It is trimmed; empty means no reason argument.
- **Console allowlist** (`normalizeRconCommand`, `RCON_COMMANDS`) stays unchanged.
- **Masking:** without `config.manage`, online addresses go through `maskIp` (bots stay `bot`) and playerids through `maskGuid`. Steamid is never returned.
- **Audit `rcon.kick`:** `{ instanceId, actor, slot, ok, code }` only.
- **Permissions:** reads need `diagnostics.read`; kick routes need `server.manage`.
- **Tests:** every new test file is registered in `scripts/preflight-4.18.14.mjs`.

## Review Focus

1. A slot that is reassigned between the list and the kick must never kick the new player. Task 2 tests that no kick packet is sent on a mismatch, and native Task 6 runs a wrong-playerid kick.
2. Names with spaces, colour codes, `^7` and digits must parse correctly from the right. Task 1 fixture.
3. A reason with forbidden characters or more than 126 chars must be rejected before any I/O. Task 1.
4. A B3 view must keep working when the server is down or RCON fails, with online shown as unknown. Task 3.
5. Ban and kick must keep the ban when the kick fails. Task 3.
